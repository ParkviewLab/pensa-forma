PensaForma mark geometry

The drawing specification for every mark on the PensaForma map canvas. Complete enough to reproduce the shapes in any language against any 2D drawing target. The companion to the UI chrome (ui-chrome.md) and the layout engine (layout-engine.md), beside this file. Each figure below renders from the same path data as the golden masters in the canonical Markdown.

This page is the presentation sibling of mark-geometry.md, which is canonical. It shows each mark on both of the application's themes, azure (the light default) and navy (the dark), because the two-theme colour meaning is part of the specification. The Markdown carries the formulas, the constants, and the full prose; this page carries the shapes.

Scope. The mark vocabulary only: the complete set of vector marks the canvas draws, for its cards, tracks, junctions, decorators, and standalone markers. Not the layout engine that positions them (row layering, branch routing, junction placement, folding, the camera), which is the layout engine's. Every position here is an input the layout supplies.

1The ground

A dot at every 40-pixel lattice point, in the low-alpha --grid ink; the subway paper. It is specified as a repeating 40×40 tile whose dot fades out by radius 1.4px; reproduced as a tiled texture, or a loop of small filled circles over the visible rectangle.

3The card silhouettes

Six shapes: four for tasks and project boundaries, and two tilted shapes for workflow boundaries, an ellipse and a narrow keystone. Each is an outer silhouette in the node colour with the same path inset per edge and refilled in the panel colour; the band between the two fills is the outline, thin on one edge and heavy on another (the mid-century tell). Every figure below is the outer path and its innerT-transformed copy, drawn on both themes. Width is a fixed 188; the height is stated per shape.

ellipse — a start node, tilted (w=188, h=58, θ=−3°)

The largest ellipse of the box's proportions that fits once rotated by the card's tilt, its major axis then held to seven tenths of that: semi-axes (63.85, 27.12) about (94, 29). The inner ellipse is the per-edge inset in the card frame, and both turn together about the centre, so the heavy side of the band tilts with the shape. The tilt is derived from the node's id, between 2 and 6 degrees either way. The note glyph, shown, anchors to the inner ellipse's inscribed corner and rotates with the mark. The label wraps to the inner ellipse's inscribed width, 84.5 px, whatever the card's height.

5The orbits decorator

A flagged node wears three off-axis elliptical rings centred on the card, each carrying one electron ball, plus a core, in the node's own colour (a task's status colour, the project teal, or the workflow line colour). Off-axis and irregular on purpose; drawn behind the card so the rings overflow it. Shown in the done violet; the faint rounded box represents the card the decorator sits behind; it is included here so that you can see how much the decorator overflows a card.

7The tracks

A track is a polyline in --line with round caps and joins: a riser (the vertical spine, width 3), and the departure and return laterals (width 2.3).

azure · a departure fan of three
navy · a departure fan of three

Illustrative, with the lanes compressed: three siblings leaving one branch point, the junction-side ramp longest for the innermost, so each flat runs at its own height and the count and order read from the verticals. The exact split is the layout engine's section 4.3.

8The underpass

Where a lateral crosses another line, it yields, cut with a gap whose ends carry caps lying parallel to the line passed under, so the cut reads as a slice of what runs on. The illustration shows a return passing behind a riser.

azure
navy

Illustrative crossing; the exact gap and cap geometry is the computation in section 8 of the Markdown (air across the crossed line, perpClear 3 plus its half-width, divided by the sine of the crossing angle). On a toolkit without arbitrary clipping, the cut becomes an explicit mitred ribbon quad; see the implementation notes.

9The junction diamond

A branch point or return point with a branch attached is marked by an 8-pixel square turned 45° into a diamond, in --line (turning to --ink on hover); every junction carries a transparent 13-pixel hit halo, shown faint, which is the return-point drop region and the hover region.

11The drop indicators

During a drag, over a legal target only, in --cursor: a chevron pair for a trunk-edge, branch-edge, or return-point target, centred on the point the drop would occupy; a bar the height of the drawing for a main-workflow target, in the gutter it would occupy. The dragged card's ghost follows the pointer at 40 % opacity.

Colours (two themes)

Every fill and stroke is a role token resolving to one of two values by theme. The line colour marks a workflow's boundaries, teal a project's, and violet a task that is done. Every mark names its tokens; the two-theme values are below.

Implementation notes

The traps an implementation meets on any drawing target, in brief (the Markdown's closing section carries them in full): flatten each quadratic to a sampled polyline, and each conic at 48 angles, before any camera transform where no native primitive exists; draw the outline as two fills, never a stroke; triangulate the concave hull and marquee before filling on a renderer that fills only convex polygons directly; apply the rotations and scales as affine operations on the point list; give every stroke round caps and joins; and where arbitrary clipping is unavailable, replace the underpass's cut strip with an explicit mitred ribbon quad. If text draws from a rasterized glyph atlas, drive zoom through world coordinates and font size, or labels blur while the vector marks stay crisp.
