PensaForma UI chrome

The design specification for the PensaForma window, menus, header widgets, right-click menus, dialogs, note editor, activity log panel, About, and Open Source Licenses windows, rendered. The canonical text is ui-chrome.md, beside this file; if the two drift, the Markdown wins. The map canvas is a black box here (the style documents and the layout engine), and drag-and-drop is the interaction document's.

This specification (the Markdown, with this page as its rendered twin) is the sole and final authority for what it covers: build exactly what it says, and where it is silent, choose any reasonable behaviour and record the choice. Nothing here presumes a rendering technology; every visual is geometry, colour, and behaviour any drawing target can honour. Every widget mock below is drawn with the specified measurements and colour tokens in Googie, the default style, light and dark (the note editor, for room, in light alone), in Googie's faces, League Spartan and Boogaloo, embedded in this file (SIL OFL 1.1). In every other style the chrome takes that style's colours and faces; its layout, sizes, strings, and behaviour do not change.

1The window and native menus

One main window, 1280 × 800 at first launch, no minimum size, standard platform window chrome, first paint in the ground colour of the style and theme that will apply on this launch (Googie's light #d3e6ef when no choice can be read). Only http(s) links open, always externally in the system's default web browser; the application itself never reaches the network except the About window's explicit check. A second launch focuses the first. On platforms whose conventions keep applications resident without windows, follow the convention; elsewhere closing the window quits.

Where the host has a native menu bar: an application menu where the platform provides one (About PensaForma, Open Source Licenses…, then the conventional services/hide/quit entries), the platform's standard File, Edit, View, and Window menus, the Edit menu opening with Undo <command> (labelled with the last command's subject, disabled when the slot is empty, no Redo), then Help (About PensaForma first on platforms with no application menu, then Open Source Licenses… and Source Code, opening the project's source page externally). On hosts with no menu bar, About, Licenses, and Undo must stay reachable through some modest affordance. No automation-server item; no custom accelerators.

A single column: the header bar above a canvas viewport that fills the rest. The viewport carries the style's ground grid on its own background (it neither pans nor zooms; Bauhaus draws none) and shows an empty-state message when there is nothing to draw. The canvas hand-off, and external writers

Four canvas gestures reach the chrome: right-click opens a context menu (a card's own, else the canvas menu; nothing with no domain or in flagged-only mode); clicking a card's note glyph opens the note editor; clicking a task's status glyph cycles todo → in-progress → completed → cancelled; double-clicking a card body toggles its flag, on any kind. External automation edits re-render in place at most once per displayed frame, camera held, and clear the undo slot; external domain create/delete refreshes the switcher, and if the open domain vanishes the editor, the log panel, and menus close and the first remaining domain opens. Requirement: a failed domain open must unload the previous domain, so no stale editing surface remains reachable through the canvas menu.

3The context menus

One widget serves the card menus, the canvas menu, and the MCP pill: fixed position at the pointer (client coordinates; shifted flush with a 4px inset at screen edges, never flipped), min-width 190, panel surface, radius 8, padding 5, shadow 0 10px 30px rgba(0,0,0,.28), 12.5px text. Every row carries a 12px check column so labels align; submenus open on hover only, anchored to their own row (left edge at the row's right edge plus 3px, top 6px above the row's top), and are not clamped. Dismissal: action, a press anywhere outside (handled before the pressed element reacts, so the menu closes at the press and a drag begun outside dismisses it immediately), Escape, scroll, resize, another right-click. No keyboard navigation.

The vocabulary the items speak, in brief (the Markdown's section 4.1 carries the full definitions, the glossary the whole vocabulary): a workflow opens at a start node and closes at a finish node; a project is a begin node, its paired end node, and everything between, and the begin card is its handle. Between consecutive nodes is a gap with a branch point below and a return point above, and "above"/"below" a node in a menu name the gap beside it. A branch is a workflow of its own departing from a branch point on the left or right, returning to a return point at or above it inside the same projects, or running open; its start node's title names it in every submenu. "Here" is a per-workflow mark on a task, moved by Make here, removed by Clear here. A wrap run is a contiguous stretch of one workflow that neither straddles a project boundary nor cuts a branch's scope; Return a branch here and Move a branch here list the branches for which the gap above the node is legal. Move up/Move down move a node to the next distinct position along its workflow; Move left/Move right reorder a main workflow.

Begin, end, start, finish, and canvas menus

Begin card: same as a task less the Status and here items; Make project becomes Make task; after the Wrap item it gains Unwrap…, Expand/Collapse, and Export to Markdown… (an OS save dialog, default name <title>.md or export.md for a blank title, writing the extent as a nested checkbox outline; the serialisation is the Markdown's section 5.1). Its Delete… deletes the whole project. Folded: the four add/return/move items on the hidden gap are absent.

End card: Add task above, Add task below, the two Add branch submenus, then Return a branch here ▸ and Move a branch here ▸ when candidates exist, a separator, Expand/Collapse (acting on the paired begin node). No note or log items: an end node carries neither. No Delete…: an end node is deleted with its begin node.

Start card: Rename…; for a main workflow Move left/Move right when a neighbour exists; Expand/Collapse (a workflow folds like a project, D15 as amended); a separator; Add task above and Add branch above ▸, both absent while the workflow is folded; a separator; for a main workflow Copy, then Export to Markdown…, the note items, Activity log…; a separator; Delete…, deleting the whole workflow. Finish card: Detach return when a branch returns; Add task below and Add branch below ▸, absent while folded; a separator; Expand/Collapse (acting on the paired start node). No note or log items: a finish node carries neither.

Canvas: New workflow…; Paste as new workflow (only with a session clipboard; an exact copy of the copied main workflow, with new ids and suffixed titles where they collide); separator; Add bookmark… (on an empty domain it silently does nothing); Jump to bookmark ▸ and Delete bookmark ▸ when bookmarks exist. Junction diamonds have no menu of their own; right-clicking one opens this canvas menu.

4The dialogs

Two primitives over a rgba(0,0,0,.35) backdrop: a text prompt (input focused and pre-selected; Enter confirms, Escape/backdrop cancels; Cancel then OK, right-aligned) and a choice dialog (buttons in order; Escape or backdrop cancels; Enter does nothing and nothing is focused). Card: at least 320 wide, at most the smaller of 90% of the window and 440, panel surface, radius 12, padding 18px 20px, shadow 0 20px 60px rgba(0,0,0,.4). No toast layer exists; every notice is one of these, except a failed note autosave, which is silent.

5The note editor

A full-window opaque overlay on the ground colour, above menus and dialogs raised from outside it; not a dialog. Opens from Edit note… on any node's menu or a click on a card's note glyph; no keyboard shortcut. Always opens in split edit mode. The title is the node's title; an end node reads the close of “<project title>” and a finish node the close of “<workflow title>”. Closes on ✕, or Escape when focus is outside the source editor; domain switch or external deletion of the node also closes it.

Source pane, toolbar, preview

The source pane is a plain-text editing area with markdown syntax highlighting and soft wrap toggled live by the Wrap button (persisted, default on). Syntax colours are tokens: headings violet bold, inline code and links teal, URLs --c-progress, list markers --c-todo, every markup marker dimmed --muted; caret --cursor; selection a 24% cursor mix. Toolbar buttons act on press without stealing the editor's focus or selection: B/I/S/</> wrap with **, *, ~~, backtick (Mod-b/i, Mod-Shift-x, Mod-e); H, List, 1., Quote prefix lines; Link inserts [text](url) with url selected (Mod-k); Code wraps in a fenced block. Insert-only: no toggle-off, no list continuation. Preview: CommonMark with the common extensions plus math ($…$, $$…$$; a malformed formula renders as visible error text), the note text treated as untrusted (nothing executes, links inert except explicit http(s)), re-rendered per keystroke; links open externally; styling per the Markdown's section 7.5.

Saving and reconciliation

No Save button. Autosave debounced 500 ms; leaving edit mode, closing, and quitting flush first; a failed write is a silent diagnostic log line. The first non-empty save records the filename on the node (the glyph appears). Emptying a note writes the empty file and keeps the glyph; only Delete note… removes it. Node deletion (any kind, any writer) never removes note files; the orphans stay in notes/, unread, until the domain itself is deleted. Filenames <nodeId>_<slug>.md (in order: title lowercased, non-alphanumeric runs collapsed to hyphens, end hyphens stripped, cut to 12, a trailing hyphen stripped again); an empty slug gives <nodeId>.md. External change while open: node deleted → close with The node whose note you were editing was removed by another writer, so the note was closed.; file changed, editor clean → silent reload; changed with unsaved edits → once, This note was changed by another writer while you had unsaved edits. Your edits are kept; save to keep them. Edits are never discarded silently.

Requirement: a Note dialog raised while the editor is open must paint above the opaque editor, not on the ordinary dialog layer beneath it (Appendix section on draw order).

5aThe activity log panel

Activity log… on any card's menu opens a non-modal panel anchored to the viewport's right edge, 380px wide, panel surface with a 1px --line edge on its left: the node's title, a primary Add entry… button, then the entries newest first, each with a meta line (local time, author, · system for an application entry, · edited once revised) and its text. Hovering an entry reveals ✎ and ✕, which open the Edit entry prompt and the Delete entry dialog. The map behind stays live; a right-click on it, Escape, or a domain switch closes the panel. An external write to the node reloads the list; an external deletion closes it silently.

A singleton, 420 × 300, fixed size, no menu bar of its own, its own dark palette independent of the application's themes. The update check runs only when the window opens (the project's release feed, 5s timeout); every failure answers unknown, never up-to-date; nothing downloads.

8Bookmarks

Surfaced only in the canvas menu: add, jump by name, delete by name with confirmation. A bookmark stores a name, the folded scopes (projects and workflows), and the ids of every node drawn wholly inside the viewport when it was saved, in a bookmarks file beside the domain file; no zoom and no camera coordinate, so it means the same thing on every client. Jumping applies the fold set to the live view and to the client's persisted view state (the fold state survives a restart), re-renders, then frames the surviving nodes with a 24px padding at a zoom no greater than 1.5; none surviving → fit plus the Bookmark location is gone dialog. No rename, reorder, update-in-place, or active indicator.

Derived colours

Every derived tint is a named token drawn at an opacity; treat them as translucent overlays or precompute the composite. Hover tints are --line at 16 % (buttons) and 20 % (menu items), the danger button's --c-progress at 16 %, the caret's line in the editor 12 %, code grounds 16 %/14 %, the editor selection --cursor at 24 %, the automation dot's inward ring --ink at 25 %. The one opaque blend, the danger button's edge (55 % --c-progress with 45 % --line), resolves in Googie to #8f5d4a light and #b79580 dark, and in other styles from their tokens. The dialog backdrop is black at 35 % opacity; the shadows are black at 28 % (menus) and 40 % (dialogs), literal values with no token behind them.

Fonts and stacking

The chrome is set in the style's faces: Fröbel Instrument Sans with Spline Sans Mono; Prairie and Bauhaus Jost throughout; Googie Boogaloo (display), League Spartan (interface), and Spline Sans Mono; Suuronen Familjen Grotesk with Spline Sans Mono. All six families are bundled under the SIL OFL 1.1. The note editor and the About window keep fixed faces in every style: Instrument Sans, with Spline Sans Mono for the note source and code. No platform font is used; a character no bundled face holds shows as an empty box. Chrome roles: brand 13px/800 display uppercase; buttons and selects 12px; percent 11px tabular; menus 12.5px; dialog titles 14px/800; note source 13px mono; note preview 16px (12–28 adjustable) with bold headings. Draw order within the window, back to front: map world, the drop indicator and ghost during a drag, the activity log panel, context menu, dialog layer, note editor, then a dialog raised from within the open editor (which must paint above it); About and Licenses are separate windows.
